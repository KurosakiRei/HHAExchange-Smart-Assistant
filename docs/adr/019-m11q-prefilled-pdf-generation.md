# ADR-019: M11Q PDF 一键预填与下载方案

## 状态
Accepted (2026-05-14)

## 背景

Issue #21 的目标是在 HHAExchange Smart Assistant 中新增一条稳定、可复用的文档生成能力：

1. 用户在悬浮面板点击按钮后，一键下载已预填病人信息的 `M11Q` PDF。
2. 当前仅有模板文件 `docs/M11Q FORM.pdf`，该模板不是 AcroForm（无可编程表单字段）。
3. 需预填 3 个字段：
   - Patient Name
   - DOB（固定格式 `MM/DD/YYYY`）
   - Fax Number（内置号码可选，也可自定义）
4. 功能入口倾向放在悬浮面板内部，避免 HHA 页面多 iframe/DOM 频繁变动造成入口失效。

本 ADR 聚焦三个核心问题：

1. 技术可行性与生成路径
2. UI 入口与交互边界
3. 配置持久化与可维护性

---

## 决策

### D1：PDF 生成技术路线 — 静态模板 + 坐标绘制（pdf-lib）

**选定**：使用浏览器端 PDF 处理库在静态模板上按坐标绘制文本，不走 AcroForm 字段填充。

理由：

1. 当前 `M11Q FORM.pdf` 无 `/AcroForm`，不具备直接 `getForm().getTextField()` 的前提。
2. 方案不依赖后端，不改变 userscript 单文件分发模型。
3. 与现有 `FaxTemplateGenerator` 的“前端本地生成 + 浏览器下载”范式一致，降低集成风险。

备选方案评估：

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| AcroForm 字段填充 | 实现简单、语义清晰 | 当前模板非 fillable，无法直接使用 | ❌ 否决 |
| 服务端生成 PDF | 可统一字体与坐标 | 需后端/鉴权/部署，违背当前架构 | ❌ 否决 |
| 继续走 docx 再导出 PDF | 复用现有 docx 技术栈 | 格式不可控，链路更长，用户体验差 | ❌ 否决 |
| 静态 PDF 坐标绘制 | 前端可落地、依赖简单、性能可控 | 需要一次坐标标定与小幅微调 | ✅ 选定 |

### D2：模板资源打包策略 — Webpack `asset/inline`（`.pdf`）

**选定**：将 `M11Q FORM.pdf` 以 `asset/inline` 打包成 base64 data URI，运行时直接加载。

理由：

1. userscript 以单文件分发，避免运行时外部文件依赖。
2. 离线可用，规避 CORS 与网络波动。
3. 与现有 `.docx` 模板内联策略保持一致，维护成本低。

### D3：UI 入口位置 — 邮件助手 Header 右侧动作区

**选定**：在 `MailBuilderTab` 自身 header 右侧新增动作按钮区，将 `创建 M11Q PDF` 放在 `当前页面：XX` 标签左侧。

理由：

1. `MultiTabPanel` 顶层 header 为全局共享容器，不适合挂病人专属动作。
2. `MailBuilderTab` 已有独立 header，扩展动作区对现有架构侵入最小。
3. 入口位于悬浮面板内部，规避 HHA 主页面 DOM/iframe 演进风险。

### D4：功能可用范围 — 仅病人页面启用

**选定**：仅在 `PATIENT_INTERNAL`、`PATIENT_NS` 页面启用按钮；其他页面展示禁用态与原因提示。

理由：

1. 该功能依赖病人姓名、Admission ID、DOB。
2. 在护理员页面启用会造成误导和错误输出。

### D5：弹窗交互模型 — 下拉内置号码 + 自定义输入 + 记忆开关

**选定**：采用轻弹窗，不做“完全无确认直接下载”。

弹窗关键行为：

1. 只读展示：Patient Name、DOB。
2. Fax Number 区域：
   - 下拉可选内置号码
   - 可切换为自定义输入
   - `记住下次默认选择` 复选框（默认勾选）
3. 按钮：`取消`、`下载 PDF`。

内置号码（固定）：

1. Main - 718-646-0680
2. Queens - 718-943-0902
3. Flushing - 718-353-2571
4. 8AV - 718-676-0957
5. Chinatown - 646-448-4353

首次默认：`8AV - 718-676-0957`。

### D6：持久化策略 — 记忆“选择模式 + 值”而非仅记号码

**选定**：持久化 `fax mode` 与对应值，支持“内置模式”与“自定义模式”无缝恢复。

建议结构：

```json
{
  "mode": "builtin",
  "builtinId": "8av",
  "customFax": "",
  "remember": true
}
```

规则：

1. 若 `remember=true` 且选择内置号码，下次恢复对应内置项。
2. 若 `remember=true` 且选择自定义号码，下次进入自定义模式并回填该号码。
3. 若 `remember=false`，下次回退首次默认（8AV）。

### D7：文件命名策略

**选定**：输出文件名格式为：

`PatientName AdmissionId M11Q.pdf`

示例：

`Wang Min AHC-123456 M11Q.pdf`

### D8：字段渲染规则（已确认）

1. 字段数量：3（Name、DOB、Fax）。
2. 页码：全部写入第 1 页。
3. 对齐：全部左对齐。
4. 字号：固定字号。
5. Patient Name：单行，不自动缩小，允许向右溢出。
6. DOB：强制格式化为 `MM/DD/YYYY`。

### D9：坐标管理方式 — 集中常量 + 一轮校准

**选定**：坐标配置集中管理，不在 UI 逻辑中硬编码散落。

建议结构：

```ts
const M11Q_COORDINATES = {
  page: 0,
  name: { x: 0, y: 0, size: 12 },
  dob: { x: 0, y: 0, size: 12 },
  fax: { x: 0, y: 0, size: 12 },
};
```

执行策略：

1. 先提交初始坐标。
2. 通过一版样张做微调（通常 ±1~5pt）。
3. 锁定坐标后进入稳定维护。

---

## 影响

### 正面

1. 将 M11Q 生成流程统一到悬浮面板，减少页面跳转和手工录入。
2. 对页面结构变化具备更高鲁棒性（入口不依赖病人页复杂 DOM 注入）。
3. 与既有“模板生成”能力模型一致，降低学习与维护成本。

### 负面 / 限制

1. 静态坐标方案对模板版式变化敏感；模板更新后可能需要重标定。
2. Patient Name 不缩放，极端长名字可能超出可视框。
3. 默认字体与模板原字形可能存在轻微视觉差异。

---

## 实施边界

1. 本次不改造成可编辑 PDF 表单（AcroForm）。
2. 本次不新增后端服务。
3. 本次不将入口放入全局 `MultiTabPanel` 顶层 header。
4. 本次不支持批量生成多个病人 M11Q。
