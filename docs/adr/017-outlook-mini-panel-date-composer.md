# ADR-017: Outlook 专用迷你悬浮面板与日期输入器域

## 状态
Accepted (2026-05-05)

## 背景

用户在日常工作中需要频繁输入多种日期文本，常见模式包括：

- 单日：`04/15/2026`
- 连续区间：`04/15 - 04/16/2026`
- 单日与连续区间混合：`04/01 - 04/02, 04/07, 04/13, 04/15 - 04/16/2026`
- 跨月区间：`04/30 - 05/02/2026`
- 跨年区间：`12/30/2026 - 01/02/2027`

当前手动输入存在以下问题：

1. 需要反复手敲斜杠、逗号、横线与空格，速度慢且容易出错；
2. 连续日期与混合日期的格式容易不统一，例如逗号后空格不一致、横线两边空格缺失、年份省略规则混乱；
3. 日期输入场景分散于 Outlook 邮件正文、HHAExchange 各类模板与后续可能新增的工具中，重复造轮子会导致维护成本上升；
4. 现有 HHAExchange 主悬浮面板尺寸固定为约 `680 x 460`，不适合常驻完整双月历或多月历 UI；
5. Outlook 页面当前只有邮件自动化适配层，没有面向用户的通用轻量面板；
6. 对 Outlook 或未知编辑器承诺“任意光标位置自动插入”风险过高，尤其在 `contenteditable`、React 受控输入与跨页面焦点切换场景下不稳定。

本次需求的核心不是“保存一串日期文本”，而是：

> 将用户当前点选的日期集合，稳定地转换为可复用、格式统一、可复制的文本结果。

---

## 决策

### D1：日期输入能力抽象为共享域，源数据使用“已选日期集合”而非结果字符串

**选定**：新增共享日期域（以下简称“日期输入器域”），内部使用 canonical 日期集合管理状态，推荐使用 `YYYY-MM-DD` 字符串集合或等价的数据结构作为源数据；结果字符串仅作为派生输出，不作为事实来源。

共享域需要承担以下职责：

- 维护当前选择的日期集合；
- 对日期集合执行排序、去重、连续区间合并；
- 根据格式 preset 生成最终文本；
- 为 HHAExchange 与 Outlook 两个宿主提供一致的行为与 UI 能力。

**理由**：

- 用户选中的原始数据是“哪些天被选中”，而不是一段已经排版完成的字符串；
- 若把结果字符串作为唯一状态，后续取消某一天、补点某一天、切换年份显示规则时都需要反向解析文本，复杂度高且脆弱；
- 以日期集合为源可以天然支持过去日期、未来日期、单日、区间、混合、跨月、跨年等全部场景。

### D2：HHAExchange 内采用独立“日期输入器”Tab，而不是塞入 MailBuilder、Header 或边框快捷入口

**选定**：在现有 HHAExchange 主悬浮面板中新增一个独立的 `日期输入器` Tab。

Tab 本体充当“工作台（workbench）”，而不是完整日历承载区。该 Tab 至少包含：

- 一个醒目的“打开日期输入器”按钮；
- 格式 preset 选择区；
- 当前结果预览区；
- `复制结果` 与 `清空` 操作；
- 可选的最近一次或最近数次输出记录。

**否决方案**：

- 放在 `MailBuilderTab` 内：该 Tab 已经拥挤，且日期输入器并不只服务邮件模板；
- 放在面板 header / 边框快捷按钮：发现性差、容易误触、并且要求先改动公共容器结构；
- 直接把双月历常驻塞进 Tab 内容区：主面板空间不足，视觉与交互都过于拥挤。

### D3：Outlook 页面采用专用迷你悬浮面板，而不是复用整套 HHA 主面板

**选定**：在 Outlook 页面单独引入一个“专用迷你悬浮面板”，视觉上沿用 HHAExchange 现有悬浮图标与面板的交互范式，但运行时与 HHA 主面板解耦。

Outlook 迷你面板只保留两个 Tab：

1. `快速搜索`
2. `日期输入器`

**理由**：

- Outlook 页面不需要状态追踪、QA、Cleaner、MailBuilder 等 HHA 专属 Tab；
- 当前 `index.ts` 在非 HHA app host 上会提前退出，不会启动主面板；
- 使用专用迷你面板可以在 Outlook 下保留熟悉的操作入口，同时避免拉入与 Outlook 无关的大量 watcher 与业务逻辑。

### D4：完整日期选择 UI 采用共享 Modal，而不是常驻面板

**选定**：日期输入器的完整选择体验由一个共享 Modal 提供，HHA 与 Outlook 的日期 Tab 都通过该 Modal 打开。

Modal 规格：

- Desktop 默认双月历并排显示；
- 窄视口可自动改为上下堆叠；
- 单击日期可切换选中/取消；
- 支持 Shift-Click 选择连续区间；
- 提供 `应用`、`清空`、`取消` 等操作；
- 侧边或底部提供实时结果预览。

**范围控制**：

- 本 ADR 要求双月历 + 单击切换 + Shift-Click 区间选择；
- 鼠标拖拽跨格连选不作为本次最小交付要求，后续如有必要再补充。

### D5：格式输出规则必须完全确定化，不能依赖用户手工修饰

**选定**：日期输入器域统一负责格式归一化，至少支持以下规则：

1. 自动排序；
2. 自动去重；
3. 自动合并连续日期为区间；
4. 逗号后永远一个空格；
5. 横线两边永远一个空格；
6. 跨月区间正常显示，例如 `04/30 - 05/02/2026`；
7. 跨年区间两端必须都带年份，例如 `12/30/2026 - 01/02/2027`。

默认提供以下三种格式 preset：

- `compactSameYear`：同一年内采用紧凑展示，例如 `04/15 - 04/16/2026`
- `fullYear`：两端均显示完整年份
- `monthDayOnly`：只显示月/日，用于少数无年份上下文场景

默认 preset 选用 `compactSameYear`。

### D6：输出策略采用“Copy First”，不对 Outlook 任意光标自动插入作出承诺

**选定**：日期输入器域在两个宿主中都必须提供稳定的 `复制到剪贴板` 能力；其中 Outlook 场景以复制为主路径。

含义如下：

- HHAExchange `日期输入器` Tab：允许用户打开 Modal 选日期，生成结果后复制使用；
- Outlook 迷你面板 `日期输入器` Tab：以复制为主路径，用户回到正文或任意输入点粘贴；
- 本次架构不承诺“在 Outlook 任意 caret 位置直接恢复并插入文本”。

**说明**：

- 对第一方、自家可控输入框的“先记录目标字段，再打开日期 Modal，完成后自动插入”的能力，可作为未来增强；
- 但这不应成为本 Epic 的核心交付，也不能阻塞 Outlook 复制路径上线。

### D7：Outlook 中的 Quick Search 必须依赖租户缓存，而不能只靠当前页面 URL 猜测

**选定**：当脚本运行在 HHAExchange 页面时，应缓存最近一次成功解析到的 tenant base URL；Outlook 下的 Quick Search 优先读取该缓存，而不是只依赖当前 Outlook 页面 URL 推导。

**理由**：

- 现有 `HhaSearchService.detectTenantBaseUrl()` 主要从当前 URL 或脚本资源推导租户；
- 在 Outlook 页面，这些上下文通常不存在，若直接回退到默认租户会带来明显风险；
- 用户对 Outlook 迷你面板中的 Quick Search 预期是“像在 HHA 页面一样可用”，租户缓存是必要前提。

### D8：宿主级持久化只保留轻量偏好，不持久化完整日期选择结果

**选定**：对 HHA 与 Outlook 两个宿主，分别持久化以下轻量状态：

- 面板位置；
- 最后激活的 Tab；
- 最后使用的格式 preset。

不默认跨页面持久化以下内容：

- 当前已选日期集合；
- 当前未复制的预览结果。

**理由**：

- 日期输入场景高度临时化，跨页面残留旧选择更容易误用；
- 轻量偏好保留可以提升效率，而不引入“昨天的日期还留在今天”的风险。

## 后果

### 正面影响

- 用户不再需要手工维护日期字符串中的标点、空格与区间逻辑；
- HHA 与 Outlook 均获得稳定、统一的日期输入能力；
- 日期相关 UI 与规则不再散落到各模板中，后续新功能可复用同一域能力；
- Outlook 页面首次拥有对最终用户可见的轻量操作面板，而不只是底层自动化适配器。

### 负面影响 / 风险

- 需要在 Outlook 页面额外维护一套迷你面板 bootstrap 逻辑；
- Quick Search 在 Outlook 下依赖租户缓存，若缓存缺失需要提供清晰的错误提示或引导；
- 用户仍需在 Outlook 场景中执行“复制 → 粘贴”两步，而不是一步自动插入；
- 双月历 Modal 与共享服务会新增一组前端状态管理代码，需要保证宿主间行为一致。

---

## 被否决的方案

| 方案 | 否决原因 |
|---|---|
| 只做 HHA 页面日期工具，不做 Outlook 面板 | 不能覆盖用户最高频的 Outlook 输入场景 |
| 只做复制按钮，不做图形化日期选择 | 无法解决日期选择本身的效率与格式统一问题 |
| 把日期入口塞到 MailBuilderTab | 作用域过窄，且 MailBuilder 已经拥挤 |
| 在 HHA 面板 header / 边框上挂一个小图标 | 发现性与可维护性都差 |
| Outlook 直接承诺“任意光标位置插入” | 技术不稳定，风险高于价值 |
| 把完整双月历常驻在 680 x 460 主面板内 | 空间不足，体验拥挤 |
